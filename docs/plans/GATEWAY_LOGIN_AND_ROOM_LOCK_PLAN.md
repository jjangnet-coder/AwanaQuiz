# [수정계획서] 최초 접속 시 [교실 선택 + 접속 코드] 통합 인증 게이트웨이 및 교실 완전 고정 UX 개편

올려주신 스크린샷과 말씀해 주신 피드백을 보면:
- 현재 방식은 메인 화면의 빈 표가 먼저 보이고, 상단 드롭다운에서 교실을 변경할 때 팝업이 뜨는 구조라 **기록관 입장에서 첫 화면이 엉성하고 어색하며, 접속 절차가 직관적이지 않습니다.**
- 사용자님께서 제안해 주신 **"접속하자마자 팝업(게이트웨이)이 떠서 [교실 선택]과 [접속 코드]를 입력하고, 인증이 끝나면 오직 그 교실로만 딱 고정되어 입력 화면이 펼쳐지는 방식"**이 훨씬 깔끔하고 보안상으로도 완벽합니다!

---

## 1. 개선되는 핵심 플로우 (Gateway Login Modal)

URL에 코드를 노출하지 않고, 모든 기록관은 동일한 공식 단일 주소(`https://.../index.html`)로 접속하여 중앙 게이트웨이 인증을 거칩니다:

```mermaid
flowchart TD
    A[기록관 단일 공식 주소로 index.html 접속] --> B{이미 인증된 교실이 브라우저에 저장되어 있는가?}
    B -- 예 (새로고침 등) --> C[저장된 교실로 즉시 자동 복구 및 잠금]
    B -- 아니오 (첫 접속) --> D[화면 중앙 게이트웨이 모달 표시 (교실 선택 + 접속 코드 입력)]
    D --> E[기록관이 '교실' 선택 및 해당 교실 '접속 코드' 입력 후 [입장하기] 클릭]
    E --> F{스프레드시트 설정의 CODE_교실명과 일치하는가?}
    F -- 불일치 --> G[붉은 경고 메시지 표시 & 접속 차단]
    F -- 일치 --> H[인증 성공!]
    H --> I[브라우저 로컬 저장소에 인증 교실 영구 저장]
    I --> C
    C --> J[상단 헤더에 '📍 스팍스1 시험장 🔒' 고정 배지 표시]
    J --> K[타 교실 접근 완전 차단 및 해당 교실 채점 진행]
```

## 2. 세부 UI 및 동작 설계

### A. 첫 접속 게이트웨이 모달 (입장 전)
- URL 파라미터 체크 로직을 완전히 제거하고, 단 하나의 깔끔한 공통 주소로 운영합니다.
- 인증되지 않은 사용자가 접속하면 뒤 배경이 완전히 블러(Blur) 처리되며 중앙에 **[기록관 교실 입장 인증]** 모달이 뜹니다:
  1. **교실 선택 드롭다운:** `[스팍스1 ~ 스팍스5, 티앤티1 ~ 티앤티7]`
  2. **접속 코드 입력창:** 4자리 접속 코드 입력 (예: `SP01`)
  3. **[교실 입장하기]** 파란색 버튼
- *취소 버튼이나 닫기(X) 버튼이 없으므로, 올바른 코드를 입력하기 전에는 시스템 내부 데이터를 일절 볼 수 없습니다.*

### B. 인증 완료 후 화면 (입장 후)
- 인증이 통과되면:
  - 게이트웨이 모달이 닫히며 상단 교실 선택 드롭다운 자리에 **`📍 [스팍스1] 시험장 🔒`** 형태의 고정 배지가 들어섭니다.
  - 드롭다운이 아니므로 다른 교실을 절대 누를 수 없습니다.
  - 우측에 작은 `[교실 변경]` 링크를 제공하여, 본부 스태프가 교실을 교체해야 할 때는 기존 인증을 해제하고 다시 게이트웨이 모달을 띄울 수 있도록 안전장치를 마련합니다.

### C. 새로고침(F5) 세션 유지
- 시험 도중 기록관이 실수로 브라우저를 새로고침(`F5`)하거나 껐다 켜더라도, 브라우저의 `localStorage`를 통해 **이미 인증된 교실로 즉시 복귀**하므로 재인증 번거로움 없이 끊김 없는 채점이 보장됩니다.

## 3. 작업 대상 파일
- `index.html`:
  1. 초기 로드 시 `LOCKED_ROOM`이 없으면 게이트웨이 인증 모달 실행
  2. 게이트웨이 모달 UI (`교실 드롭다운` + `접속 코드 입력창`) 추가
  3. 인증 성공 시 `localStorage`에 인증 교실 저장하여 새로고침 시에도 고정 유지
  4. 상단 헤더의 교실 표시부를 고정형 배지로 전환
