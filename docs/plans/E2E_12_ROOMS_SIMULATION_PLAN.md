# 12개 시험장 실시간 클릭 시뮬레이션 테스트 구현 계획서

## 1. 개요 및 목적
본 계획서는 **AwanaQuizScore** 시스템에서 12개의 시험장(1~12시험장)이 동시에 퀴즈 점수를 입력할 때, **실제 사용자 클릭 이벤트**를 기반으로 점수가 정상적으로 전송되고 **본부 관리 포털(`admin/index.html`)**에 실시간으로 반영되는지 검증하기 위한 E2E(End-to-End) 시뮬레이션 테스트 구축 방안을 정의합니다.

---

## 2. Playwright란?
**Playwright**는 Microsoft에서 개발한 오픈소스 **브라우저 자동화 도구**입니다.
- 실제 Chrome(Chromium) 브라우저를 코드로 실행하고 제어합니다.
- 사람이 마우스로 버튼을 클릭하고, 입력창을 누르고, 화면을 스크롤하는 것과 동일한 **실제 DOM 클릭 이벤트**를 발생시킵니다.
- 하나의 스크립트에서 **여러 개의 독립된 브라우저 창(Context)**을 동시에 띄워, 12명의 채점자가 각자 다른 PC/브라우저에서 접속해 작업하는 것과 같은 환경을 재현할 수 있습니다.

---

## 3. 테스트 아키텍처

```text
[Playwright 테스트 러너 (Node.js)]
  ├── 브라우저 1  ──▶ index.html (1시험장 로그인/선택 → 클릭으로 점수 입력)
  ├── 브라우저 2  ──▶ index.html (2시험장 로그인/선택 → 클릭으로 점수 입력)
  ├── ...
  ├── 브라우저 12 ──▶ index.html (12시험장 로그인/선택 → 클릭으로 점수 입력)
  │
  └── 브라우저 13 ──▶ admin/index.html (본부 관리 포털 실시간 수신 모니터링 및 검증)
```

- **독립 세션**: 12개 시험장 브라우저는 각각 독립된 `BrowserContext`를 사용하여 `localStorage`, 쿠키, 세션이 서로 섞이지 않습니다.
- **시각적 확인**: `headless: false` 옵션으로 실행하면 실제 브라우저 창이 화면에 뜨므로, 점수가 입력되는 과정과 본부 포털에 들어오는 모습을 눈으로 직접 확인할 수 있습니다.

---

## 4. 시뮬레이션 시나리오 (단계별 흐름)

### 1단계: 환경 준비 및 접속
- 로컬 정적 서버(예: `npx serve` 또는 Python `http.server`)로 `AwanaQuizScore` 웹 앱을 실행합니다.
- 13개의 브라우저(1~12시험장 + 본부 관리 포털 1개)를 띄웁니다.
- 각 시험장 브라우저는 해당 시험장 번호(1~12)를 선택/진입합니다.

### 2단계: 오전 객관식 퀴즈 입력
- 12개 시험장이 동시에(또는 약간의 시차를 두고) 오전 객관식 퀴즈 화면으로 이동합니다.
- 각 시험장마다 실제 버튼 클릭으로 점수를 입력합니다.
- **현실성 부여**: 한 번에 쫙 입력하지 않고, 클릭 간격에 랜덤 지연(예: `300ms ~ 1,200ms`)을 주어 실제 채점자가 터치/클릭하는 속도를 모방합니다.
- 입력 완료 후 제출/저장 버튼을 클릭합니다.

### 3단계: 오후 객관식 퀴즈 입력
- 오전 객관식 완료 후, 오후 객관식 퀴즈 탭/화면으로 이동하여 동일하게 실제 클릭 이벤트와 랜덤 지연으로 점수를 입력 및 제출합니다.

### 4단계: 오후 스피드 퀴즈 입력
- 오후 스피드 퀴즈 화면으로 이동하여 실제 클릭 이벤트로 점수를 입력 및 제출합니다.

### 5단계: 본부 관리 포털 실시간 검증
- 본부 관리 포털(`admin/index.html`) 창에서 12개 시험장의 오전/오후 객관식 및 오후 스피드 퀴즈 점수가 실시간으로 수신·갱신되는지 확인합니다.
- 스크립트 종료 전, **각 시험장이 클릭해서 입력한 예상 점수**와 **본부 포털에 표시된 실제 점수**를 자동 비교하여 누락이나 오차가 없는지 최종 리포트를 출력합니다.

---

## 5. 폴더 및 파일 구성 (안)
기존 HTML 및 Google Apps Script 코드에는 영향을 주지 않도록 `test/` 폴더 하위에 테스트 환경을 구성합니다.

```text
test/
├── e2e/
│   ├── package.json            # Playwright 의존성 관리
│   ├── playwright.config.js    # 브라우저 실행 옵션 (화면 표시, 타임아웃 등)
│   └── simulate-12-rooms.spec.js # 12개 시험장 + 본부 포털 시뮬레이션 스크립트
```

---

## 6. 기대 효과 및 검증 항목
1. **동시성 검증**: 12개 시험장이 동시에 점수를 제출할 때 Google Apps Script(`Code.gs`) 백엔드에서 데이터 유실, 덮어쓰기, 잠금(Lock) 오류가 발생하지 않는지 확인합니다.
2. **UI/UX 반응성 확인**: 실제 클릭 이벤트 발생 시 화면 상태 변경, 저장 중 표시, 오류 복구(Self-healing) 동작이 정상 작동하는지 검증합니다.
3. **실시간 동기화 확인**: 본부 관리 포털에서 12개 시험장의 점수가 지연 없이 정확하게 집계되는지 확인합니다.

---

## 7. 향후 진행 순서
1. `index.html` 및 `admin/index.html`의 실제 버튼/입력창 선택자(Selector) 파악
2. `test/e2e` 폴더에 Playwright 설치 및 초기 설정
3. 1개 시험장 대상 단일 시뮬레이션 테스트 작성 및 동작 확인
4. 12개 시험장 동시 실행 + 본부 포털 검증 스크립트로 확장 및 실행
