# [수정계획서] 교실 단위 1회 프리패치(0.001초 교시 전환) 및 점수 제출 초고속화 방안

## 1. 개요 및 사용자 질문 답변

### Q. "11개 핸드북 시상/석차 계산 분리는 언제 어떻게 진행되나요?"
- **답변:** 
  - **방안 (실시간 자동화 유지 + 핀포인트 초경량화):**
    - 기존에는 점수 1개가 들어올 때마다 **11개 핸드북 전체(1,376명 전원)의 석차/메달을 매번 무식하게 다시 계산**해서 5~8초가 걸렸던 것입니다.
    - 개선 후에는 **"지금 점수가 들어온 바로 그 1개 핸드북(예: 행글라이더 1학년, 약 100명)"만 핀포인트로 즉시 계산**합니다!
    - **효과:** 시상 시트의 실시간 석차·메달은 여전히 자동으로 즉시 반영되면서도, 서버 연산량이 1/11로 줄어들어 **점수 제출 속도가 1~2초대로 대폭 단축**됩니다!
    - 대회 종료 후 본부에서 전체 시트를 최종 마감할 수 있도록 Apps Script 에디터에 `recalculateAllAwards()`(전체 일괄 계산) 함수도 함께 비치합니다.

## 2. 핵심 개선 내용

### A. 교실 단위 1회 프리패치 & 교시 변경 0.001초 즉시 전환 (`index.html`)
1. **교실 인증 직후 딱 1회만 해당 교실 전체(1~7교시) 데이터 프리패치:**
   - 게이트웨이에서 `스팍스1` 인증 완료 시, **`스팍스1` 교실에 해당하는 1~7교시 선수 명단(약 70~100명, 불과 20KB)**만 백엔드에서 딱 1번 가져옵니다. (1~2초 소요)
2. **교시(1~7교시) 클릭 시 네트워크 통신 0회 (Zero-Latency):**
   - 이미 메모리에 해당 교실의 1~7교시 데이터가 모두 들어있으므로, 점수기록관이 교시를 변경할 때 **구글 서버를 호출하지 않고 0.001초 만에 즉시 화면을 렌더링**합니다.
   - 더 이상 5~10초 동안 로딩 팽이가 도는 일이 완전히 사라집니다!

3. **교실 변경 버튼을 직관적인 [로그아웃] 버튼으로 변경:**
   - 상단 교실 고정 배지 옆의 `[교실 변경]` 버튼을 **`[🔓 로그아웃]`** 버튼으로 변경합니다.
   - 클릭 시: 채점 미제출 상태일 경우 이탈 경고 팝업 후, 안전하게 현재 교실 세션을 종료하고 최초 게이트웨이 로그인 창으로 전환합니다.

---

### B. 점수 제출 응답 속도 대폭 단축 (`Code.gs`)
1. **타겟 핸드북 핀포인트 시상 연산 적용 (`updateSingleHandbookAwards`):**
   - 점수 수신 시(예: `행글라이더 1학년 1조`), 11개 시트를 전부 돌지 않고 **해당 학생이 속한 `행글라이더 1학년` 시트 딱 1개만 0.3초 만에 갱신**합니다.
   - 11개 시트 순회로 인한 극심한 딜레이를 제거하여 점수 제출 속도를 **1~2초대**로 단축합니다.
2. **트랜잭션 락(Lock) 점유 시간 최소화:**
   - 동시 제출이 일어나는 대회 피크 시간대에도 서버 대기열이 밀리지 않고 원활하게 저장됩니다.
