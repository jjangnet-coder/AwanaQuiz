# [수정계획서] 저장 UX 개선 및 버튼 명칭/동작 방식 최적화

## 1. 현재 저장 구조 및 의문점 분석

### ① "저장 버튼을 누르지 않으면 저장이 안 되나요?"
* **현재 동작 원리:**
  1. **브라우저 로컬 저장 (자동 즉시 저장):** 문항을 클릭할 때마다 브라우저의 `localStorage`에 0.01초 만에 자동 저장됩니다. 따라서 실수로 새로고침을 누르거나 창을 닫아도 **입력한 내용은 로컬에 100% 그대로 복구**됩니다.
  2. **중앙 Google 시트 저장 (수동 버튼 전송):** 상단 버튼을 눌러야만 비로소 **중앙 Google 스프레드시트(로그 시트 + 최종집계 시트)로 점수가 최종 전송**됩니다.
* **이유 (수동 전송을 두었던 배경):**
  - 8~10개 문항을 채점하는 도중에 문항 클릭 1번마다 Google 시트로 매번 네트워크 요청을 보내면(학생 20명 × 8문항 = 160회 요청 폭주), Apps Script 할당량 초과 및 트래픽 부하가 발생할 수 있어 **"한 교시 채점이 다 끝난 후 한 번에 제출"**하도록 설계되었습니다.

---

## 2. 개선 및 해결 방안

### ① 버튼 명칭 직관화
* **문제점:** `채점 완료 저장`은 '지금까지 채점한 걸 파일로 저장하는 건가?' 하는 애매함이 있습니다.
* **추천 변경안:**
  - **대안 A (가장 추천): `📤 점수 최종 제출`** (또는 `📤 채점 결과 제출`)
    - *의미:* 현장 기록관이 교시 종료 후 본부 서버로 결과를 최종 보고/제출한다는 뉘앙스가 가장 명확함.
  - **대안 B: `☁️ 중앙 서버 전송`**

---

### ② 미제출(실수) 방지 안전장치 강화 방안 (선택 옵션)

현장 기록관이 입력을 다 해놓고 **제출 버튼 누르는 것을 깜빡 잊는 사고**를 막기 위한 2가지 보완책:

1. **옵션 1 (안전 알림 팝업 + 미제출 시각 표시):**
   - 로컬에는 입력되었으나 아직 중앙 시트에 제출하지 않은 변경사항이 있을 때, 버튼 색상을 눈에 띄게 깜빡이거나 `[미제출 점수 있음]` 배지 표시.
   - 마지막 8번(또는 10번) 문항 채점이 완료되는 순간 **"채점이 완료되었습니다. 지금 본부로 제출하시겠습니까?"** 안내 팝업 자동 호출.
   - 페이지를 벗어나거나 교실/교시를 바꿀 때 미제출 점수가 있으면 경고창 표시.

2. **옵션 2 (디바운스 자동 제출):**
   - 클릭할 때마다 바로 쏘지 않고, 채점 입력이 끝난 뒤 5초 동안 추가 입력이 없으면 백그라운드에서 Google 시트로 조용히 자동 전송.
   - *주의점:* 네트워크가 불안정한 환경에서는 제출 여부를 기록관이 확인하기 어려울 수 있음.

---

## 3. 권장 적용 계획
1. 버튼 라벨을 **`📤 점수 최종 제출`** 로 변경
2. **미제출 상태 시각화:** 입력 후 아직 제출하지 않은 데이터가 있으면 버튼이 주황색 `[📤 변경사항 최종 제출]`로 강조되고, 제출 완료 시 녹색 `[✅ 제출 완료]`로 변경
3. 마지막 문항 입력 완료 시 제출 유도 알림 및 페이지 이탈 방지 경고 적용
