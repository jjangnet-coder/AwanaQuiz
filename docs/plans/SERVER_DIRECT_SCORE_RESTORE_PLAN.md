# [수정계획서] 구글 시트(서버) 직결 실시간 O/X 답안 복원 아키텍처 개편 (No Local Storage)

## 1. 개요 및 설계 원칙
- **문제 인식:**
  - 로컬 캐시(`localStorage`)는 기기별 상태 불일치, 시트 리셋 후 과거 데이터 잔류 등 치명적인 부작용을 유발합니다.
  - 사용자님의 지적대로, **브라우저 로컬 캐시를 완전히 배제하고 오직 구글 스프레드시트(중앙 서버)의 로그 데이터에서 직접 O/X 답안을 읽어와 화면에 복원**하는 순수 서버 중심 아키텍처(Single Source of Truth)로 구축합니다.
- **원칙:**
  1. 기기나 브라우저 어디에도 채점 데이터를 캐싱하지 않음.
  2. 서버(구글 시트)에 이미 제출된 답안이 있다면 새로고침/재로그인/기기변경과 무관하게 **서버의 실제 O/X 채점표가 화면에 즉시 복원**됨.
  3. 관리자가 구글 시트를 초기화하면 서버에 데이터가 없으므로 웹 앱도 즉시 **100% 깨끗한 빈 상태로 자동 동기화**.

---

## 2. 상세 구현 계획

### A. 백엔드 API (`Code.gs`): 로그 시트의 문항별 O/X 답안 포함 반환
1. **`doGet(e)` 확장:**
   - 교실 프리패치(`action=getRoomStudents&room=...`) 또는 교시 조회 시:
   - `객관식_로그` 및 `스피드_로그` 시트를 확인하여, 해당 교실의 선수들이 이미 제출한 **최신 문항별 O/X 답안(`submittedAnswers`)** 맵을 생성하여 함께 반환합니다:
     ```javascript
     // 반환 구조 예시
     submittedAnswers: {
       "P1186_1_오전": ["O", "O", "O", "O", "O", "O", "O", "O"],
       "P1188_1_오전": ["O", "O", "O", "O", "O", "O", "O", "X"]
     }
     ```
   - 이미 서버에 기록된 최신 감사 로그의 문항별 정답을 정확히 가져옵니다.

### B. 프론트엔드 (`index.html`): 서버 답안 기반 테이블 자동 렌더링
1. **`initGridAndRender()` 복원 로직:**
   - 화면을 그릴 때, 서버에서 전달받은 `MASTER_DATA.submittedAnswers[studentId + '_' + period + '_' + session]`가 존재하는지 확인합니다.
   - **서버 답안이 존재하는 경우:**
     - 1번~8번(또는 10번) O/X 셀을 서버 답안으로 완벽하게 채웁니다.
     - O수, X수, 총점이 실시간 자동 계산되어 화면에 즉시 표시됩니다.
     - 버튼 상태를 **`[✅ N교시 제출 완료]`** 녹색으로 자동 설정합니다.
   - **서버 답안이 없는 경우 (새 시험 or 시트 초기화 상태):**
     - 100% 깨끗한 빈 채점판(`''`) 및 `[📤 N교시 점수 제출]` 대기 상태로 표시됩니다.
2. **복원 후 수정 및 재제출 지원:**
   - 복원된 상태에서 점수기록관 선생님이 특정 문항의 O/X를 클릭하여 수정하면:
   - 버튼이 즉시 **`[📤 N교시 점수 최종 제출 (수정됨)]`** 주황색으로 전환되어 구글 시트로 최신 수정본을 즉시 재제출할 수 있습니다.

---

## 3. 효과
- **로컬 캐시 0% 사용:** 로컬스토리지 불일치 문제가 원천적으로 사라집니다.
- **언제 어디서든 완벽한 상태 일치:** 태블릿을 껐다 켜거나 다른 기기에서 접속해도 구글 시트에 제출된 실제 데이터가 정확하게 화면에 뜹니다.

## 4. 변경 대상 파일
1. `google-apps-script/Code.gs` (doGet 시 제출 로그의 문항별 O/X 맵핑 포함 반환)

3. `docs/plans/SERVER_DIRECT_SCORE_RESTORE_PLAN.md` (문서화)
