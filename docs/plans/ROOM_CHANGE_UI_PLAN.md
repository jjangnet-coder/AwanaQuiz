# [수정계획서] 교실 변경 인터페이스(UI) 및 안전 이탈 메커니즘 상세 설계

## 1. 개요 및 사용자 질문 답변
- **질문:** "인증 후 교실이 고정되면, 교실을 변경할 수 있는 UI가 있을까요?"
- **답변:** **네, 반드시 있어야 합니다!** 현장 운영 중 본부 스태프가 다른 교실을 점검하거나, 기록관의 교실 배치가 변경되었을 때 유연하게 대처할 수 있도록 **상단 고정 배지 옆에 직관적이고 안전한 `[교실 변경]` UI 버튼**을 제공합니다.

---

## 2. 교실 변경 인터페이스(UI) 상세 설계

### A. 상단 헤더의 교실 표시 형태 (인증 완료 후)
인증이 완료되면 상단 헤더 컨트롤 영역에 다음과 같이 표시됩니다:

```html
<!-- 상단 헤더 교실 표시 영역 -->
<div class="room-lock-badge-group">
  <span class="badge-locked-room">
    📍 <span id="currentRoomText">스팍스1</span> 🔒
  </span>
  <button class="btn-change-room" onclick="requestRoomChange()">
    교실 변경
  </button>
</div>
```

- **시각적 형태:** 
  - `📍 스팍스1 🔒` : 파란색 둥근 배지 (현재 교실 고정 강조)
  - `[교실 변경]` : 깔끔한 연회색 소형 텍스트 버튼 (`font-size: 0.78rem`, hover 시 밑줄)
  - 실수로 툭 건드려 눌리지 않도록 서브 버튼 스타일로 정돈합니다.

---

### B. 교실 변경 클릭 시 동작 (2중 안전장치)

1. **미제출 변경사항 인터셉트 (실수 방지 1단계):**
   - 만약 현재 교시의 채점을 진행 중인 상태(`SUBMIT_LIFECYCLE_STATE === 'in_progress'` 또는 `'ready'`)에서 `[교실 변경]`을 누르면:
     - 커스텀 경고 모달:
       > ⚠️ **미제출 변경사항 안내**  
       > 현재 [N교시] 채점 결과가 아직 서버로 제출되지 않았습니다.  
       > 교실을 변경하시면 작성 중인 채점 내용이 초기화됩니다. 정말 이동하시겠습니까?
     - `[계속 진행]`, `[취소]`

2. **교실 변경 확인 (실수 방지 2단계):**
   - 진행을 누르면 브라우저의 기존 인증 세션(`localStorage`)을 안전하게 초기화합니다.
   - 즉시 화면 중앙에 다시 **[교실 입장 인증]** 게이트웨이 모달(`교실 선택` + `접속 코드`)이 깔끔하게 열립니다.
   - 새 교실과 새 코드를 입력하여 다른 교실로 입장할 수 있습니다.

## 3. UI 와이어프레임 미리보기

```
+-----------------------------------------------------------------------------------------------------+
| AWANA 성경퀴즈대회 점수 입력 시스템  [SPARKS]       기록관: [김상학  ]  [📍 스팍스1 🔒] [교실 변경]     |
|                                                   교시: [ 1교시 ▼ ]  [ 📤 1교시 점수 제출 ] [🔄 새로고침] |
+-----------------------------------------------------------------------------------------------------+
```

- 기록관에게는 본인 교실이 확실히 잠겨 있음을 시각적으로 확인시켜 주고,
- 변경이 필요할 때는 `[교실 변경]` 버튼을 통해 안전하게 다시 게이트웨이 모달로 전환할 수 있습니다.
